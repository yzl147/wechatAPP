## 当前实施状态

路线图阶段 0～7 的核心代码任务已经完成：

- 固定基础库 `3.15.2`，建立 `npm run check`。
- 完成云端权限、并发初始化、输入校验、错误处理和饮食记录分页。
- 收藏、库存、采购状态、生活清单和候选餐单已迁移为云同步，并保留版本化本地缓存。
- 建立 `domain / repositories / services / components` 分层及公共设计组件。
- 完成“今天吃什么”两阶段转盘及候选管理。
- 完成首页、今日饮食清单、记录、菜谱、生活清单、库存与本月回顾的重点体验优化。
- 清理旧点餐术语、本机配置、未使用页面、核心 Emoji 图标以及价格和订单状态协议。
- 饮食记录采用软删除，单条记录删除后可在详情页撤销；单条和批量删除的记录也可从“最近删除”逐条恢复，不会物理移除数据库文档。
- 生活清单项目、整张生活清单和库存食材使用统一的删除确认、处理中状态及成功/失败反馈。

上述状态表示代码和自动检查已完成；微信开发者工具与真机结果仍以每轮实际人工验证为准。

## 当前决策

- 保留原生微信小程序、JavaScript、WXML、WXSS、Glass-Easel 和微信云开发。
- 暂不引入 TDesign。当前自建组件已覆盖主要需求，可避免增加包体和视觉体系混用。
- 保留 `cart/order` 页面路由、云函数名和集合名作为历史兼容边界，不进行无收益的数据迁移。
- 历史数据库中的价格、金额和订单状态字段不批量改写，读取时过滤。

## 后续候选工作

1. 完成小屏 Android、全面屏 iPhone、大字体、长内容、断网和快速点击的发布回归。
2. 观察生活清单真实使用频率，再决定是否调整底部导航。
3. 后续可评估库存优先推荐、转盘决策历史和经用户确认的库存扣减。

每次只选择一个边界清楚的事项实施，不将发布回归、数据迁移、功能增强和视觉调整混入同一提交。
