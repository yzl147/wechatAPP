# 个人数据存储策略

## 决策

记事微清单的个人持久数据最终以云端为唯一事实来源，本地存储作为缓存、离线副本和首次迁移来源。公共菜谱继续使用云端公共集合；饮食清单和饮食记录继续按 OpenID 隔离。

| 数据 | 目标来源 | 本地用途 |
|---|---|---|
| 生活清单、完成历史、库存 | 云端 | 缓存、离线只读和旧数据迁移 |
| 菜谱收藏、采购勾选 | 云端 | 缓存和旧数据迁移 |
| 页面筛选、加载状态、转盘动画状态 | 页面或本机 | 临时状态，不同步 |
| 转盘候选餐单 | 云端按 OpenID 隔离 | 缓存；后续功能阶段实现 |

## 实施顺序

1. 为现有本地数据增加 `schemaVersion`、迁移前备份、校验和异常降级；v2 会从首次 v1 备份中补回缺失项目，当前数据优先。
2. 迁移生活清单、完成历史和库存；迁移接口使用稳定业务 ID 保证重复执行不产生重复项。
3. 迁移收藏和采购勾选。
4. 云端写入成功后更新本地缓存；网络失败时保留本地旧数据和待同步状态，不以空响应覆盖本地数据。

## 冲突原则

- 云端文档保存 `updatedAt` 和修订号，写入使用修订号检查，避免静默覆盖其他设备的更新。
- 首次迁移按稳定业务 ID 合并；相同 ID 以较新的 `updatedAt` 为准。
- 无法识别的本地数据先备份，再返回安全默认值，不删除原始数据。
- 自动迁移必须可重复执行，并记录迁移版本；未完成前不清除本地来源。
