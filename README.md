# 记事微清单

一个帮助自己整理日常生活事项的微信小程序。它不试图替代复杂的待办或笔记软件，而是把经常会忘、需要反复准备的一件小事，变成一张随手可勾选、可留存的清单。

目前，小程序从“今天吃什么”这个最明确的场景开始：周末挑选菜谱、组成今日清单；工作日也可以快速记录外出用餐和外卖。后续会围绕同样的轻量清单体验逐步扩展，而不是重新变成点餐、购物或订单系统。

## 产品定位

- **服务对象**：以自己和家庭日常生活为主的个人用户。
- **核心形式**：按场景创建、勾选并留存清单。
- **设计原则**：少填写、少步骤、打开就能用；每个功能都应解决一个真实且重复出现的生活场景。
- **不做的事**：外卖点餐、支付、配送、商家订单与复杂社交功能。

## 当前功能：今天吃什么

1. 浏览菜谱，按分类筛选、收藏并查看做法；收藏可跨设备同步。
2. 将想做的菜加入“今日清单”，可调整份数或删除。
3. 支持自己做、外出吃和点外卖三种饮食记录方式；外出和外卖可快速填写店铺/地点与菜品。
4. 回顾某一天吃了什么；自己做的记录可一键复用一餐。
5. 菜品图片在运行时从云存储加载；仓库中的本地图片保留为数据源，不打包进小程序。

## 功能规划

清单能力优先围绕“准备一件事”来扩展，建议按以下顺序推进。

### 第一阶段：完善做饭场景

- **食材缺口清单**：已实现。根据今日所选菜品列出食材，勾选家中已有的部分后，剩余项即为采购清单。
- **食材库存与保质提醒**：已实现。可记录数量和保质日期，并按过期、临期、正常状态排序显示。
- **菜单与记录优化**：已支持收藏常做菜、按日期查看饮食记录、从历史记录一键复用一餐。

### 第二阶段：通用生活清单

- **家务清单**：已提供家务模板，支持逐项勾选和补充项目，并可设置每天、每周或每月循环。
- **出行/收纳模板**：已提供出行、露营、搬家和换季收纳模板。
- **自定义清单**：已支持自定义名称与项目，清单可持续编辑、删除并保存为模板。

### 第三阶段：轻量回顾

- **日历记录**：已支持通过月历查看饮食记录与生活清单完成记录，并可查看完成时的清单项目。
- **简单统计**：已支持本月饮食记录、常做菜、临期食材和生活清单完成情况。

## 信息架构设想

现有“菜谱 / 清单 / 记录”三栏可以自然演进为：

| 页面 | 近期职责 | 后续演进 |
| --- | --- | --- |
| 首页 | 在饮食清单与生活清单之间选择场景 | 展示当天各类清单的概览 |
| 饮食清单 | 管理今日做饭清单 | 连接菜谱、采购与库存 |
| 生活清单 | 家务、出行与自定义待办 | 逐步沉淀更多常用模板 |
| 记录 | 查看已保存的自己做、外出吃和外卖记录 | 日历化的生活清单完成记录 |

菜谱是饮食清单下的选菜入口，不再作为小程序首页；饮食清单和生活清单在首页同级呈现。

## 技术栈

- 微信小程序原生框架
- 微信云开发（菜谱、饮食清单、饮食记录及用户数据同步）
- 带版本迁移的本地缓存（离线读取、首次迁移和轻量页面状态）

## 项目结构

| 目录/文件 | 说明 |
| --- | --- |
| `pages/index/` | 菜谱列表与筛选 |
| `pages/detail/` | 菜品详情与做法 |
| `pages/cart/` | 今日饮食清单；目录名为历史路由兼容名称 |
| `pages/orders/` | 饮食记录列表与快速新增入口；目录名为历史路由兼容名称 |
| `pages/meal-record/` | 外出用餐、外卖的快速记录表单 |
| `pages/order-detail/` | 单条饮食记录详情；目录名为历史路由兼容名称 |
| `cloudfunctions/manageDishes/` | 菜品数据与云存储图片映射 |
| `repositories/cloud/meal-list-repository.js` | 隔离今日饮食清单的数据访问及旧云协议 |
| `services/meal-list-service.js` | 今日饮食清单的页面无关业务接口 |
| `cloudfunctions/manageCart/` | 今日饮食清单云函数；函数名和 `carts` 集合暂为旧数据兼容名称 |
| `cloudfunctions/manageOrders/` | 饮食记录云函数；函数名和 `orders` 集合暂为旧数据兼容名称 |
| `utils/` | 兼容入口、日期和版本化本地缓存等通用能力 |

## 开发约定

- 界面文案使用“菜谱、今日清单、饮食记录”，避免再使用点餐、购物车、订单、配送等业务表述。
- 新客户端代码使用 `dish / mealList / mealRecord / saveRecord`；历史页面路由、云函数名和集合名只有在兼容边界内才能继续使用旧名称。
- 每个新增模块都应先明确：它解决的生活场景、最少需要记录哪些信息，以及完成后是否值得保留历史。
- 提交信息遵循仓库根目录 `.gitmessage`：`type` 和 `scope` 使用英文，其余内容使用中文。
